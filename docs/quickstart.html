Quick start

Advance HRIS is a multi-component application, not a hosted application on GitHub Pages. This guide walks through a local test environment.

Prerequisites

  • Git
  • Docker Engine / Docker Desktop with Compose v2
  • An OpenAI-compatible API key to enable the optional AI service

1. Clone and start core HRIS

git clone https://github.com/SilverLine-Ravija/Advance-HIRS-System.git
cd Advance-HIRS-System
docker compose up --build

The base stack brings up PostgreSQL, applies migrations, starts the Go business API and then starts Next.js.

Open localhost:3000 and check localhost:8080/health from your development machine.

2. Enable the AI assistant

For local development only, provide a model provider key and start the agent overlay. Never commit secrets or expose the agent directly to the public internet.

export OPENAI_API_KEY='your-provider-key'
docker compose -f docker-compose.yml -f docker-compose.agentic.yml up --build

Sign in to the web portal and open localhost:3000/assistant. The model provider must support OpenAI-compatible tool calling. The agent is a private component and uses the existing authenticated Go HRIS endpoints.

3. Try a governed action

  1. Ask the assistant to check an authorized leave balance or list your pending requests.
  2. Ask it to prepare a leave request.
  3. Review the proposed action and confirm it only in the local demo environment.
  4. Check the result in the Leave workspace. Manager approval still follows the normal HRIS policy.
Use synthetic employee data. Local bootstrap/demo credentials in the repository are not intended for production. Before using real personnel data, follow the production readiness checklist and review the AI security model.

4. Test the complete Docker workflow without a paid AI key

bash scripts/agent-docker-smoke.sh

The test uses an isolated mock model and synthetic demo data, exercises the authenticated web-to-agent flow, and shuts down the disposable database volume afterward. Do not run it against real employee data.
